## Class Diagram – Backend (CodeThium Server)

LLM provider hierarchy arranged left-to-right with namespace swimlanes
grouping classes by responsibility layer.

```mermaid
classDiagram
    direction LR

    namespace Base {
        class BaseLLMProvider {
            <<abstract>>
            +chat(messages) Promise
            +chatStream(messages) AsyncGenerator
            +getModelName() string

    }

    namespace OpenAI_Compatible {
        class OpenAICompatibleProvider {
            -baseURL string
            -apiKey string
            -model string

            +getModelName() string

    OpenAICompatibleProvider <|-- OpenRouterProvider
```

### Class responsibilities

| Swimlane | Class | Description |
|---|---|---|
| **Base** | `BaseLLMProvider` | Abstract base — defines the `chat` / `chatStream` / `getModelName` contract |
| **OpenAI Compatible** | `OpenAICompatibleProvider` | Shared OpenAI-format HTTP fetch + SSE parser inherited by all cloud providers |
| **Cloud Providers** | `GroqProvider` | Thin wrapper for api.groq.com — default provider, low latency |
| | `OpenRouterProvider` | Thin wrapper for openrouter.ai — auto-fallback when Groq returns 429 |
| | `GeminiProvider` | Adds `chatStreamMultimodal()` for image and PDF payloads via Google AI Studio |
| | `GemmaProvider` | Extends Gemini; filters `<thought>` blocks from Gemma 4 31B output |
| **Local** | `LocalModelProvider` | Hybrid pipeline: Groq classifies → ONNX model generates code → Groq verifies |
